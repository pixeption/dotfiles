Standing rules: Do only the listed acceptance items; hold only the resources named as held, never
touch those named off-limits; never spawn sub-agents.
If a command fails because a project is held
by another editor, stop and report; never retry or poll. Classify every failure (introduced /
pre-existing with evidence / unknown), no opportunistic refactors.
Add a test only for observable behavior, an invariant, a boundary or a bug that reached an
integrated target, and only when no existing test covers it; prefer a new case or assert in the
item's existing test over a new method, because every test is run and maintained forever. A fix
for a review finding on unintegrated work extends the item's tests or adds none. Report the
decision as `tests: +<n> (<what each pins>)` or `tests: +0 (covered by <test>)`. New tests are
plain by default: write an Integration test (AssetDatabase, prefabs, scenes, rendering, Play Mode)
only when a plain test cannot observe the behavior, because Integration tests dominate suite time.
The item's score is an estimate: more files or work than expected is not a reason to stop.
Stop only when the approach does not work or the work needs something the brief rules out, and
report `Outcome: Needs decision` (`Blocked` after two attempts), which goes to the advisors.
Give a fail-before for every new test: run it red against the old code only when the change fixes
a bug that reached an integrated target or the test runs outside Unity; otherwise state it as
reasoning (`asserts X; the old code yields Y at file:line`), because a Unity red run costs two
extra recompiles. Run, once at the end of the round, the item's test filter — its own test classes
and its callers', as the item's section names them, narrowed to your piece when the brief names one — with --filter,
fast and Integration alike, and nothing else: never a full suite, a whole category or another
item's filter, because the orchestrator lands the item on that filter's count and runs the full
suites at the plan's gates. A GameCore filter that selects more than
one Integration test borrows the test shards (workspaces "Borrow the test shards").
No single command blocks for more than 270 s (Bash timeout < 300000), because past 5 idle minutes
your prompt cache goes cold and the next turn re-writes your whole context: run anything longer in
the background and check on it in waits of at most 240 s.
A compile break in another agent's file is reported once. At most two materially different attempts at a blocker;
after the second, STOP and report (Goal / Discovered / Blocker / Tried / Options / Need from
orchestrator). Report in the return format below, always with the Cost line (context now / turns /
elapsed). When the context hook tells you to pause, finish the current step at a safe point (tree
compiling, editor not in Play, isolation restored), write what a successor needs (suite command and
last green count, uncommitted files, half-done work, editor and Play-mode state), report
`Outcome: Paused`, end with `BEES: results=<unit>:paused:-[;…]` and start nothing else. Your last
line is always the `BEES: results=…` line, one entry per unit; every commit subject names its unit.
No report, no commit: when the required verification includes a Unity test run and that run
produced no XML in this session, leave the tree dirty and report Blocked; verification that is not a
Unity run records each command, its exit status and result instead, because evidence must match
the required verification.
Never run `git reset --hard`, `git checkout -- <path>`, `git stash`, `git clean` or
`git add -A`/`-u`/`.` in a tree that carries someone else's uncommitted work: stage by explicit
path, and recover a mistake by re-applying from a copy.
