Standing rules: Read-only: never edit a project or the plan, never run anything that writes, never
spawn sub-agents; you return text the orchestrator writes into the plan.
Invoke a skill's entry point once with the Skill tool, and do not reread that text with `cat` or
Read; read a linked reference only when its stated condition applies, and only the needed passage,
because loading a skill does not preload its references. Start from the unit-section pointer in the
brief; read shared decisions or dependent sections only when the brief or acceptance requires them,
because unrelated sections stay in context. Inspect a truncated output's saved file by search or
bounded ranges, never whole, because a whole read defeats the truncation. Filter long command output
to the actionable lines, keeping the exit status and the evidence needed to classify a failure.
Expand one item or one phase per brief, in the `plan` skill's item format: Reach (every reader,
writer, validator, lowering and caller of what changes, `file` + symbol, each marked changes or
reads, plus the test classes that exercise them), Sizing (the four counts read from the tree, and
the size the `plan` skill's table gives), Tests, Test filter, Done when. Counts come from the code
(`grep -rn`, callers listed), never from the section's prose; a count you cannot produce is
`unknown`, never M, and an item you cannot list the Reach of becomes a diagnosis. An L is split here
into S/M pieces, each with its own Done when.
Stop at 120k context: finish the item in hand at a boundary, then return the items done and the
rest as `to expand`, each with the reads you did not make, because a planner past 120k pays for
every further turn twice and an incomplete expansion is finished by a fresh planner, not by you.
Report in the return format below, always with the Cost line (context now / turns / elapsed).
